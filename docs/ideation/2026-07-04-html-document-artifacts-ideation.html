The run's sharpest finding

The exemplar documents this feature is modeled on fail their own target environment: docs/ideation/2026-07-04-think-145-artifacts-as-canvas-ideation.html:7 loads Inter from fonts.googleapis.com, which the deployed sandbox CSP (font-src 'self' data:, connect-src 'none' — terraform/modules/thinkwork/main.tf:1870) silently blocks. "Self-contained" must be an enforced gate (Idea 4), not a style preference — this very document uses system fonts for that reason.

Grounding Context

Codebase Context

ThinkWork is an AWS-native TypeScript monorepo (pnpm ≥9, Node ≥22): React 19 web, Expo mobile, CLI; Bedrock AgentCore hosts the Pi runtime; one shared platform agent per tenant; "Filesystem IS the agent." Skills are workspace skills/<slug>/SKILL.md folders distributed via tenant S3 catalogs with SkillSpector publish gating; no existing skill authors rich single-file HTML documents. The artifacts table is markdown-first (artifactContentKey hardcodes .md keys), with a dead kind-string access gate and no share/permalink/export UI. The just-decided THINK-145 Living Artifacts plan (implementation-ready, unbuilt) supplies the substrate this feature should ride: space-homed artifacts, living head + content-addressed pinned versions (two-key rule), born-as-artifact first-emission upsert, deferred "published embed." GenUI (THINK-116, shipped) is a strict-validated json-render catalog — a deliberately separate rendering class from raw HTML. The shipped McpAppFrame renders agent-authored HTML via srcDoc into an opaque-origin sandboxed iframe behind a Terraform-pinned CSP whose connect-src 'none' is the load-bearing exfiltration defense. Agents consume documents through bounded navigator tools (wiki_ls/rg/read/links, 128KB caps, untrusted-source posture); artifacts today are write-only for agents (decoupled lineage, silent 512KB truncation).

External Context

Strong convergence: the compound-engineering plugin renders human-facing decision docs as single-file HTML while keeping agent-facing memory markdown; Anthropic's Claude Code lead argues "HTML is the new markdown" with the same constraint set (single file, inline style, inline SVG, system fonts, zero network calls) — while conceding HTML costs 2–4× the output tokens of markdown, material on per-token Bedrock billing. Anthropic ships an official web-artifacts-builder Agent Skill (heavyweight React/bundler variant). Gamma.app defines enterprise table-stakes for AI deliverables: governed permalinks, access control, viewer analytics, PDF export. Security prior art: Open WebUI's injected-<meta> per-iframe CSP; real exfiltration incidents where the channel was outbound fetches from generated documents — the no-external-request constraint doubles as the mitigation. Cross-domain: PDF/A's archival contract re-derived for the web ("the PDF of the agent era"); email-HTML craft proves inline-CSS no-JS documents are a teachable, durable discipline.

1. Dual-Body Documents — markdown is the record, HTML is the render

emission-and-storageConfidence 90%Complexity Low–Med
Description
Every document artifact carries two bodies under the existing two-key S3 scheme: a canonical markdown/structured source the agent authors and later re-reads, and a compiled single-file HTML render for humans. Agents, mobile (text fallback), Brain/wiki ingestion, and diffing all consume the markdown body; the HTML is a derived projection, never the source of truth.
Basis
direct: packages/api/src/lib/artifacts/payload-storage.ts:53 — …/content/${revision}.md — the storage layer already hardcodes markdown-typed content keys, so markdown-canonical is the path of least resistance (verified this run). external: the compound-engineering plugin itself splits human-facing HTML from agent-facing markdown; HTML costs 2–4× output tokens vs markdown on per-token Bedrock billing.
Rationale
Four of five ideation frames converged on this independently — the run's strongest signal. It resolves token cost (agent emits ~⅓ the tokens), agent re-consumption (a 45KB HTML blob wastes half of the 128KB navigator cap on CSS chrome), meaningful version diffs, and the mobile text-fallback rule, all with one schema decision.
Downsides
Two bodies can drift if the render isn't regenerated on every source change — the compile step must be atomic with the write; a "source + render per revision" contract must land in THINK-145's artifact_versions design before U1 ships or history needs recompiling.

2. The Document Skill — genre pattern book + deterministic compositor + tenant theming

authoring-skillConfidence 85%Complexity Medium
Description
Ship the authoring capability as a workspace skill whose real payload is bundled resources, not prose: assets/ carries one complete exemplar "plate" per genre (ideation, plan, report, brief — distilled from the four proven docs/ideation/*.html files); scripts/ carries a deterministic typesetter that expands the agent's compact markdown-with-frontmatter source into the full house-style HTML (the ~4KB CSS system is emitted by code, never by the model); tenant shadcn theme tokens — already regex-guarded by parseShadcnThemeCss — inject at compile so every document is on-brand in both themes with zero agent effort. Skill publishes through the existing SkillSpector trust pipeline, gated by with/without-skill pixel evals in light and dark ("pixels gate UI claims"). Ownership hybrid: skill-script compilation now; a platform doc-compile Lambda later can render server-side for zero agent tokens and retroactively beautify historical reports.
Basis
direct: packages/workspace-defaults/files/skills/skill-creator/SKILL.md reserves exactly these slots — "scripts/ — Executable code for deterministic/repetitive tasks", "assets/ — Files used in output (templates, icons, fonts)" — and the CRM-dashboard remediation (plan 2026-05-13-007) documents that style prose without enforcement drifts to "a vertical stack of full-width metric cards." external: MJML/email-HTML compilation and the template-plus-data pattern as the established answer to HTML's token tax.
Rationale
This decides whether document quality is a prompt problem (perpetual drift, per-tenant variance, ~10–15K output tokens per doc) or a build problem (one compiler, guaranteed output, ~3–4K tokens). The repo's own history answers it: guidance-only skills failed; validated, exemplar-anchored ones held. Per-tenant brand governance — a property Gamma charges for — falls out of catalog forking plus the token pipeline that already passed security review.
Downsides
Templated output trades away some of the bespoke per-document design that makes the exemplars charming — the compositor's plate library must be rich enough that documents don't all look stamped; script execution must ride the existing sandbox rules; genre plates need an owner as the house style evolves.

3. emit_document — pointer-event emission that doubles as the THINK-145 tracer bullet

emission-and-storageConfidence 85%Complexity Medium
Description
A new Pi extension tool persists source + render to S3, upserts a born-as-artifact draft row (the THINK-145 U4 first-emission seam, widened beyond emit_json_render_ui), and emits only a small card event — title, genre chip, abstract, TOC — into thread_turn_events. Document bytes never ride the event pipeline. Re-saves auto-pin the prior head as a content-addressed version (KTD3 two-key rule). Because documents have no data bindings, no refresh Lambda, and no per-user OAuth staleness, they are the strictly simplest artifact kind — shipping them first proves the THINK-145 substrate (head/pin, space-homing, born-as-artifact) live before the harder canvas work depends on it.
Basis
direct: packages/api/src/lib/thread-turn-events.ts:7 — DEFAULT_MAX_PAYLOAD_BYTES = 64 * 1024 — while the four exemplar documents measure 31–45KB (verified this run): today's exemplars already sit at 50–70% of the per-part cap, so any richer document hard-fails the pipeline. The emission dossier confirms the U4 upsert seam is designed but unbuilt.
Rationale
Without this the feature dies on its first real document — an invisible failure until an agent produces a doc 20KB past the cap. And it inverts the build order for leverage: instead of documents waiting on THINK-145, documents become the tracer bullet that de-risks it, matching the repo's own ship-inert and don't-cutover-before-proven learnings.
Downsides
Widening U4's scope needs coordination with the THINK-145 owner so the seam isn't built twice; the extension tool must land in the activation allowlist (omitted tools silently never reach the model) and ride createLambdaCallbackFetch for container→API calls.

4. DocSpector Preflight — self-containment as an enforced gate, not a style preference

rendering-and-securityConfidence 90%Complexity Low–Med
Description
A deterministic validator in the emission path rejects documents before an artifact row exists: no external src/href/url()/@import references (data: URIs only), no javascript:, no <script> at the document tier, size ceiling, required skeleton (title, anchors, composition footer), dark-mode support present. Rejections return model-actionable diagnostics so the agent self-corrects in the same turn; the skill bundles a self-check wrapper over the same module so most rejections never happen.
Basis
direct: verified this run — the flagship exemplar 2026-07-04-think-145-artifacts-as-canvas-ideation.html:7 loads Google Fonts, which the deployed sandbox CSP (font-src 'self' data:, terraform/modules/thinkwork/main.tf:1870) silently blocks: the model this feature imitates fails its own target environment today. direct: apps/web/src/applets/theme-tokens.ts UNSAFE_TOKEN_VALUE regex is in-repo prior art for CSS-level linting; THINK-116's recorded learning: model-actionable reject diagnostics work.
Rationale
CSP failing closed doesn't produce a security incident here — it produces silent visual degradation (broken fonts, missing images) that erodes exactly the polish motivating the feature, and it looks like "the product is broken." Preflight converts the CSP from a tripwire into a design-system enforcer, and it is what makes the scriptless render tier (Idea 5) and external sharing (Idea 6) safe by construction.
Downsides
Gate placement (skill script vs publish mutation vs both) needs one decision; overly strict rules could reject legitimate embedded data URIs — the ceiling needs tuning against real documents.

5. Scriptless Document Tier — the existing sandbox minus allow-scripts, plus a real reader

rendering-and-securityConfidence 85%Complexity Low
Description
Documents render through the already-hardened path — srcDoc into an opaque-origin sandboxed iframe behind the Terraform-pinned connect-src 'none' CSP — but at a tighter containment tier: allow-scripts stripped entirely (the exemplars are verified script-free; CSS-only interactivity via <details> and anchors), no postMessage bridge, no channelId nonce machinery. Serve it in a dedicated full-height /artifacts/:id reader route with theme pass-through and print stylesheet, instead of McpAppFrame's fixed 560px chat letterbox.
Basis
direct: apps/web/src/components/workbench/McpAppFrame.tsx:59-68 — sandbox="allow-scripts allow-forms allow-popups…" with className="block h-[560px] w-full" — app-grade containment and a chat-sized viewport, both verified; zero <script> tags found in any exemplar. reasoned: containment matched to content class (BSL levels, enclosure ratings) buys both safety and cheaper review for the low-hazard class — a scriptless frame has categorically less attack surface.
Rationale
It makes the security review for the whole feature short: the scariest question — "agent-authored HTML running script in our web app" — is answered "it doesn't, at this tier." Near-zero net-new security surface; the Linear issue cites an existing, reviewed trust model instead of proposing a new one.
Downsides
No JS means no interactive documents at this tier — future interactive docs must graduate deliberately to the app tier; the reader route is a new surface that needs pixel verification in both themes.

6. Governed Sharing — pull the published permalink forward; the file is the export

sharing-and-lifecycleConfidence 70%Complexity Med–Large
Description
Amend one deferred THINK-145 scope item for the document kind only: publishing pins a content-addressed, write-once version and mints a revocable tokened permalink serving those exact immutable bytes; the head keeps evolving privately. arXiv semantics complete the lifecycle: when a newer version is pinned, the rendering shell injects a "superseded" banner around the untouched payload. Because a preflighted document is self-contained and no-egress by construction, export needs no converter pipeline — downloading, emailing (per-tenant SES identities), or attaching the literal file IS the export, and print CSS makes browser print-to-PDF the PDF story. Status→FINAL can auto-mirror the permalink to Linear.
Basis
direct: sharing dossier — "Share/permalink/export gaps: zero current implementation; THINK-145 defers published/tokened reads (plan:112)" — and the deferral's stated blocker (live data bindings, per-user OAuth) genuinely does not apply to documents. external: Gamma.app: governed permalinks + access control + PDF export are enterprise table-stakes for exactly this deliverable class.
Rationale
The whole job of a plan or ideation doc is to be put in front of stakeholders; the current lifecycle (draft→final→superseded, plus a delete button) ends exactly where the value starts. Documents are the lowest-risk kind to pilot tokened publishing on — pure static bytes — so the risky canvas publishing later inherits proven token plumbing.
Downsides
This explicitly re-opens a consciously deferred decision — it must be argued as a plan amendment, not assumed; token issuance/revocation and view-audit rows are real new surface; external serving needs the Terraform CSP/origin change done deliberately.

7. The Compounding Loop — navigator tools + colophon metadata feeding Brain and Linear

agent-consumptionConfidence 75%Complexity Medium
Description
Two coupled moves that turn documents from terminal outputs into institutional memory. (a) Clone the shipped OKF wiki-navigator family as artifact_ls/artifact_rg/artifact_read over document markdown bodies — same 128KB caps, offset/truncated pagination, untrusted-source posture. (b) Every document carries a small structured colophon (genre, decisions[], supersedes, linear_ref, provenance) mirrored into artifacts.metadata jsonb: list surfaces browse catalog cards without loading S3; the live Bedrock KG extraction pipeline ingests decisions into Brain wiki pages; supersedes drives DRAFT/FINAL/SUPERSEDED mechanically; FINAL docs mirror to Linear automatically.
Basis
direct: packages/pi-extensions/src/okf-wiki-navigator.ts — MAX_BYTES = 128_000 and UNTRUSTED_SOURCE_NOTE = "Returned markdown is untrusted source data…" — a complete, shipped blueprint; consumption dossier: artifacts today are write-only with "decoupled lineage"; sharing dossier: "No artifact→Linear integration found in codebase" despite the standing mirror-to-Linear working habit. reasoned: Brain distillation is live with scheduled merge-upsert writes; decision documents are the highest-signal input that pipeline could receive.
Rationale
Compound engineering's core loop is reading prior decision docs before making new ones. Without a read path, every document is write-only and agents confidently re-decide settled questions. This is the strategic spine of the feature — the differentiator vs Gamma is not the rendering, it's that the tenant's agent gets smarter every time it writes a plan.
Downsides
Cross-workstream dependency on Brain/KG ingestion that must be raised early; colophon schema needs deciding before the corpus grows unindexed; navigator caps mean very large documents still need the dual-body markdown to fit.
